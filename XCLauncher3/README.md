# XCLauncher3 — основной лаунчер (`ecarx.launcher3`)

Лаунчер Zeekr 001 (главный экран, карточки, карта, карточка медиа). `sharedUserId=android.uid.system`,
подписан platform-ключом, лежит в `/data/app/ecarx.launcher3-*/base.apk` (обновлённая системная копия).

## Файлы

| Файл | Что это |
|---|---|
| `XCLauncher3_original_3.0.2747.apk` | лаунчер, снятый с машины перед правкой (прошивка 5.6d, `3.0.2747+20260616`): уже с Яндекс.Навигатором на карте. База для `ya_widget` |
| `XCLauncher3_ya_widget.apk` | **наша сборка** на базе `3.0.2747`: Яндекс Музыка вместо QQ Music в карточке медиа и виджет Яндекс Погоды вместо штатной карточки погоды (см. ниже) |
| `ya_widget/` | исходники этой сборки: патч, новые классы, `build.sh` |

Более старые сборки (`mod_final` на базе `3.0.2745`, стоковый лаунчер 5.6) убраны из рабочего дерева,
но остались в истории git (коммит `4ee8bd86`): `git show 4ee8bd86:XCLauncher3/XCLauncher3_mod_final.apk`.

## Яндекс Музыка в карточке медиа (`ya_widget`)

Карточка медиа на главном экране (виджет `com.zeekr.mediawidget`, внутри лаунчера) получает данные только от
штатного «Медиацентра» (`com.zeekr.mediacenter`) для приложений Zeekr (QQ Music, радио, USB, Bluetooth).
Яндекс Музыка про медиацентр ничего не знает, но публикует обычную Android `MediaSession`. Патч превращает
эту сессию в карточку.

### Как это работает

```
Яндекс Музыка ── MediaSession ──► YandexBridge ──► MediaCenterRepository.mediaLiveData ──► MediaCard / CommonAudioView
                                      ▲                                                       │ кнопки ⏮ ▶/⏸ ⏭
                                      └──────── MediaController.transportControls ◄───────────┘
                                                (через MediaCenterPlayControl)
```

| Что | Где | Как |
|---|---|---|
| Новый класс `YandexBridge` (+ `$Cb`, `$Lst`, `$Tick`) | `ya_widget/smali_classes2/.../mediawidget/yandex/` | Слушает активные медиасессии (`MediaSessionManager`, право `MEDIA_CONTENT_CONTROL` есть у лаунчера как у system uid), находит `ru.yandex.music`, на каждое изменение метаданных/состояния собирает `Media` и кладёт его в `mediaLiveData`; раз в секунду публикует позицию в `progressLiveData` |
| Тип карточки | `Media.mediaType = 0x65` | выбирает вид `CommonAudioView` (обложка, название, исполнитель, ⏮ ▶ ⏭, прогресс) |
| Статус воспроизведения | `mapStatus` | карточка считает «играет» статусы Zeekr `1`/`11`, «загрузка» — `6`; Android `PLAYING(3)` → `1`, `BUFFERING(6)` → `6`, остальное → `2`. `Media.playStatus` — `final`, поэтому пишется через reflection |
| Обложка | `coverOf` | bitmap из метаданных сохраняется в кэш лаунчера (`ya_cover_0..3.png`), иначе берётся URI обложки (шаблон `%%` → `400x400`). Путь пересчитывается только при смене трека |
| Кнопки | `MediaCenterPlayControl` (патч в начале `play`/`pause`/`playNext`/`playPre`) | если в карточке сейчас Яндекс (`YandexBridge.isActive()`), команда уходит в `MediaController.getTransportControls()` и в медиацентр не попадает |
| Строка в списке источников | `SoundsourceAdapter`, `SoundSourceView` | строка QQ Music (`com.zeekr.media.qq`) показывается как «Яндекс Музыка» с иконкой приложения; нажатие выбирает Яндекс источником карточки (без сессии — заглушка «Нажмите ▶») |
| Запуск моста | `MediaCard.init` | `YandexBridge.start(context)` |

Если сессии Яндекса ещё нет, ▶ шлёт медиакнопку Play (поднимает сервис Яндекса) и открывает приложение.

### Теперь Яндекс — настоящий источник медиацентра

Позже Яндекс Музыка стала штатным источником самого медиацентра (приборка, кнопки руля, список источников) —
см. `../MediaCenter/README.md` и `../ZeekrCoreService/README.md`. Лаунчеру для этого нужны две правки списка источников
(патчи `03` и `04`); `YandexBridge` и правки QQ-строки из `01` остаются как запасной путь для карточки
(строка QQ из списка теперь убирается медиацентром, поэтому её переименование/нажатие фактически не срабатывает).

| Патч | Что |
|---|---|
| `03-hide-qq-source` | список источников фильтруется (`YandexBridge.dropQq`, копия без `com.zeekr.media.qq`); настоящему источнику `ru.yandex.music` ставится иконка приложения |
| `04-source-list-height` | высота выпадающего списка = число строк × высота строки + штатные отступы (в стоке фиксирована под 5 строк, при 4 был пустой хвост) |

Установка всего набора по порядку: `ZeekrCoreService` → `MediaCenter` → `XCLauncher3`, затем отключить QQ Music и «极享»
(команды в `../MediaCenter/README.md`).

### Ограничения

- нет перемотки по полосе прогресса, ♥ и режима повтора для Яндекса;
- пока Яндекс не выбран и не играл, карточка показывает прежний источник;
- `YandexBridge` пишет в лог (`adb logcat | grep YandexBridge`) строку на каждое обновление — так проще отлаживать;
- привязано к именам классов лаунчера `3.0.2747`; на другой версии патч может не наложиться (тогда править руками).

### Сборка

```bash
cd ya_widget
./build.sh                       # -> ../XCLauncher3_ya_widget.apk
./build.sh <другой стоковый.apk>  # на другую версию лаунчера
```

Меняется `classes2.dex` и строки карточки автомобиля в `resources.arsc`; остальное берётся из стока без изменений.
Подпись — platform-ключ из `../../platform`.

## Русская карточка автомобиля

Карточка `车况` (поездки, расход, давление в шинах) рисуется лаунчером; отдельное приложение
«Мой автомобиль» — `com.ecarx.mycar`, его русификация и исправление вылетов находятся в `../XCMyCar/`.

`ya_widget/ru/vehicle-card.json` переводит 17 строк карточки: заголовки, переключатели поездок,
подписи времени/пробега/расхода, описание графика и единицы измерения.
`ya_widget/tools/ru_vehicle_card.py` заменяет значения в глобальном пуле строк `resources.arsc`,
сохраняя номера строк, ID ресурсов, пакеты ресурсов и их конфигурации.
Это позволяет перевести карточку без полной пересборки ресурсов лаунчера.
Обозначение расхода `kWh/100km` оставлено штатным: более длинное русское обозначение
обрезается у правого края компактной карточки.
Каждый запуск проверяет наличие исходных строк, обратное чтение всего пула
и побайтовое сохранение следующих за ним пакетов. Поддерживаются UTF-8 и UTF-16;
изменение строки с форматированием span останавливает сборку.

Перевод включён в обычный `./ya_widget/build.sh`; Яндекс Музыка и Погода остаются в той же сборке.

### Установка

```bash
adb install -r -g XCLauncher3_ya_widget.apk       # та же версия и подпись — обычный -r
```

Откат: `adb install -r -g -d XCLauncher3_original_3.0.2747.apk`.
После установки лаунчер перезапускается, 3D-вид машины грузится около минуты.

## Яндекс Погода вместо штатной карточки погоды

Штатная карточка погоды (`com.zeekr.weather.WeatherFragment`) остаётся, но поверх неё размещается **настоящий
Android-виджет** приложения Яндекс Погода (`ru.yandex.weatherplugin`).

### Как это работает

| Что | Где | Как |
|---|---|---|
| Класс `YandexWeatherHost` | `ya_widget/smali_classes2/com/zeekr/weather/` | `AppWidgetHost` (id `0x59570001`): выделяет `appWidgetId`, привязывает его к провайдеру (`bindAppWidgetIdIfAllowed` — право есть у system uid), создаёт `AppWidgetHostView` и добавляет на весь корень карточки |
| Точка подключения | `WeatherFragment.onCreateView` (патч `02-yandex-weather-widget.patch`) | перед `return` вызывает `YandexWeatherHost.attach(context, root)` |
| Какой виджет | `Settings.Global` `ya_weather_widget` | имя класса провайдера. По умолчанию `ru.yandex.weatherplugin.YandexBigWeatherWidget` (текущая погода, «ощущается», ветер, давление, почасовой прогноз). Другие: `YandexWeatherWidget` (компактный: город, температура, иконка), `YandexNewHorizontalWeatherWidget`, `YandexHorizontalWeatherWidget`, `YandexClockWeatherWidget` |
| Сохранение | `SharedPreferences` `ya_weather` → `id` | `appWidgetId` переживает перезапуск; при смене провайдера старый id удаляется, привязка делается заново |

Данные и обновления приходят от самого приложения Яндекс Погода (город, сеть, периодическое обновление — раз в час и при запуске приложения).
Штатные данные карточки (погода от машины) остаются под виджетом и на экране не видны.

### Первая настройка

Виджету Яндекса нужна одна настройка: пока она не пройдена, он показывает индикатор загрузки.
Поэтому при первой привязке лаунчер сам открывает экран настройки виджета (`APPWIDGET_CONFIGURE`):
выберите оформление (тёмный фон) и нажмите **«Создать виджет»**. Дальше всё работает само.
Город берётся из приложения Яндекс Погода («Текущее место»).

### Если виджет бесконечно загружается

Проверено на машине 03.11.2026: у лаунчера был привязан `appWidgetId=66`, но в Яндекс Погоде
настройки существовали только для других id. Привязка в Android сама по себе не означает,
что настройка виджета завершена: лаунчер сохраняет id **до** нажатия «Создать виджет»
и при следующем запуске повторно настройку не открывает. Обновление погоды и интернет
при этом могут работать исправно.

Чтобы завершить настройку существующего виджета, не сбрасывая данные приложений:

```bash
# узнать текущий id (чтение файла требует root в ADB)
adb shell cat /data/user/0/ecarx.launcher3/shared_prefs/ya_weather.xml
# в dumpsys найти тот же id: hostId=1498873857, pkg=ecarx.launcher3
adb shell dumpsys appwidget
# пример для id=66 и провайдера YandexBigWeatherWidget; подставить свой id
adb shell am start -W -a android.appwidget.action.APPWIDGET_CONFIGURE \
  -n ru.yandex.weatherplugin/.widgets.settings.SetupBigWidgetActivity \
  --ei appWidgetId 66 -f 0x10008000
```

В открывшемся экране нажать **«Создать виджет»** и вернуться на главный экран.
Флаги `NEW_TASK | CLEAR_TASK` открывают новую настройку с указанным id, убирая прежнюю
задачу Яндекс Погоды, которая могла содержать настройку другого виджета.
Для другого провайдера нужен соответствующий экран настройки.
Один `APPWIDGET_UPDATE` отсутствующую настройку не создаёт.
После восстановления проверены отображение прогноза и сохранение виджета после перезапуска лаунчера.

```bash
# сменить виджет (после этого перезапустить лаунчер; откроется настройка нового виджета)
adb shell settings put global ya_weather_widget ru.yandex.weatherplugin.YandexWeatherWidget
adb shell am force-stop ecarx.launcher3
# вернуть по умолчанию
adb shell settings delete global ya_weather_widget
```

### Ограничения

- нужны установленное приложение Яндекс Погода и интернет в машине;
- виджет перекрывает штатную карточку целиком, поэтому её разворачивание (прогноз по дням) недоступно; нажатие на виджет обрабатывает само приложение Яндекс Погода (не проверялось);
- виджет рисуется со своим фоном/шрифтами Яндекса, а не в стиле Zeekr; цвет и прозрачность фона — на экране настройки;
- при сбросе данных лаунчера или смене провайдера настройку нужно пройти заново.

Нота в **нижней панели** — это не лаунчер, а SystemUI; она переделана отдельно (см. `../SystemUI/README.md`).
