# ZeekrMonitoring — VictoriaMetrics + Grafana

Сервер для метрик из `../ZeekrExporter` (приложение на головном устройстве).

| Сервис | Порт на 192.168.200.7 |
|---|---|
| VictoriaMetrics | 8300 |
| Grafana (admin / `GRAFANA_PASSWORD`) | 8301 |

```bash
cp .env.example .env && $EDITOR .env      # задать GRAFANA_PASSWORD
docker compose up -d
```

Указать адрес приёмника в приложении на машине:

```bash
adb shell am start -n zeekr.exporter/.MainActivity --es url http://192.168.200.7:8300
```

Проверка: `curl 'http://192.168.200.7:8300/api/v1/label/__name__/values'` — должны появиться метрики `zeekr_*`.

VictoriaMetrics принимает точки с любой меткой времени, поэтому данные, накопленные в буфере во время обрыва связи,
встают в графики на свои места. Метка `car="zeekr001"` добавляется при импорте.

## Дашборды (переписаны из CarlosCuezva/dashboards-Grafana-Teslamate)

TeslaMate хранит поездки и зарядки как готовые сессии в PostgreSQL, а его дашборды — SQL к этим таблицам.
Здесь данных-сессий нет, поэтому есть два слоя:

1. `sessionizer/` — контейнер: раз в 5 минут находит поездки (скорость ≥ 1 км/ч, пауза > 5 мин) и зарядки
   (разъём AC/DC или ток > 0,5 А, пауза > 10 мин) в сырых метриках и пишет по ним метрики
   `zeekr_drive_*` / `zeekr_charge_*` (метка `id` = время начала, время точки = конец сессии).
   Пересчитывает последние 72 ч, поэтому данные, догруженные после обрыва связи, попадают в свои сессии;
   устаревшие `id` удаляются. Сессия «закрывается» через 10 минут после окончания.
2. `gen/` — генератор JSON дашбордов (`python3 gen/build.py` → `grafana/dashboards-json/`), `gen/validate.py` прогоняет
   все запросы через VictoriaMetrics.

| Оригинал | Здесь | Что изменено |
|---|---|---|
| overview | Zeekr — Обзор | нет Net/Gross/Firmware/Driver temp; состояние выводится из скорости и тока |
| current-charge-view | Текущая зарядка | «добавлено в сессии» = выбранный период |
| tire-pressure | Давление в шинах | «на последней поездке» заменено графиками |
| states | Состояния | без таблицы переходов |
| drives, charges | Поездки, Зарядки | из метрик sessionizer; стоимость — оценка по тарифам |
| drive-tops | Топы поездок | нет «пробег между зарядками» |
| charging-tops, charging-costs-stats | Топы зарядок, Стоимость | AC/DC вместо SuC/Other DC; тарифы — переменные |
| charging-curves | Кривые зарядки | мощность от SOC за выбранный период; нет сетей быстрой зарядки |
| battery-health | Состояние батареи | ёмкость = энергия из сети × КПД / прирост SOC (AC, ≥ 10 %) |
| locations | Места | только координаты (нет геокодера), нужен GPS |

Переменные дашбордов: `battery_capacity` (кВт·ч), `ac_price`, `dc_price`, `ac_eff`, `min_dist`.

### Допущения, которые нужно проверить на реальных данных
- `zeekr_speed` в км/ч (иначе поправить `SPEED_TO_KMH` в compose).
- Зарядка определяется по `ID_CHARGING_PLUG_STATE_AC/DC >= 3` или току area=1 > 0,5 А. Для DC-зарядки значения
  неизвестны — проверить первую DC-сессию (в DC-режиме напряжение/ток area=1 могут быть нулевыми, тогда
  «из сети» и мощность не посчитаются, а «добавлено» останется по SOC).
- Ёмкость 100 кВт·ч (по расчёту: 0,8 % SOC за 15 мин при 3,2 кВт).
- `HVBATTUDC × 0,25` = В; `HVBATTCAP × 0,1` = А·ч. `BATT_SOC_RAW` не совпадает с текущим SOC и для процента не используется; точный SOC — `SENSOR_TYPE_BATTERY_LEVEL`.
